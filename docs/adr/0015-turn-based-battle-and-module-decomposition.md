# ADR-0015: 仲間指示型ターン制戦闘ループと「あなた」実体化・ファイル責務再編

- Status: Accepted
- Date: 2026-09-16

## Background

初期プロトタイプの戦闘システムは、「選択した仲間がボタン入力で即座に攻撃し、成否が出る」という単発のクリッカー形式であった。
また、主人公（プレイヤー）は HP も持たず、戦闘画面にも登場しない「安全地帯の透明な操作者」として扱われていた。
さらに、ゲーム機能の拡張に伴い、UI 描画、各画面の入力処理、テキスト整形、アニメーション演出のすべてが `src/main.rs` に集約され、1,900 行近くに達する巨大ファイルとなって保守性が限界を迎えていた。

## Circumstances

1. **戦闘のサスペンスと不服従の希薄化**:
   - ボタンを押した瞬間に攻撃が成功するかサボるかが判定される方式では、ADR-0003（隠し影響度と自律行動）の「仲間に指示を出したあと、本当に動いてくれるか」というハラハラ感が生じなかった。
   - 敵の反撃やターン概念が存在せず、防御や回復の戦術的価値が機能していなかった。
2. **「パンピー主人公」の非実体化**:
   - ADR-0005 で定めた「特別な力を持たない一般人主人公」がゲーム内の実体（HP・被ダメージ・狙われる危険・パンピーならではの道具や逃走判断）として存在せず、ロールプレイとルールが乖離していた。
3. **`main.rs` の肥大化と神ファイル化**:
   - ADR-0014 で入力関数の分割やチェンジディテクションが導入されたものの、コード自体の配置場所が `src/main.rs` に集約されたままであり、UI、戦闘入力、街入力、演出が混然一体となっていた。

## Rationale

1. **仲間への指示 → ターン進行ループ（クラシックJRPG形式）の採用**:
   - 「指示フェーズ（あなたと仲間全員の行動決定）」と「ターン解決フェーズ（順次実行＆メッセージ送り）」を分離する。
   - ターン解決時に仲間の影響度ロールを行い、服従・サボり・暴走がターンの流れの中で展開されることで、ドラマ（創発的ストーリー）が生まれる。
   - モンスター撃破時はダラダラと連戦に持ち込まず、即座に戦闘を終了して街へ生還させることでテンポを保つ。
2. **「あなた（一般人）」のパーティ正式参戦とルイーダの酒場（控え）分離**:
   - 騎士アルヴィンを将来のルイーダの酒場（パーティ編成所）用の控え（`ReserveRoster`）へ移し、パーティ No.1 に「あなた（一般人、HP 20）」を実体化。
   - 敵の攻撃対象に「あなた」が含まれ、ヤンデレ（ミレイ）の身代わり庇いなど「仲間の人間関係が生死に直結するサスペンス」を確立する。
3. **ファイル責務のドメイン別再編**:
   - UI 構築・整形・演出を `src/ui/` へ集約。
   - 戦闘入力を `src/battle/input.rs`、街・探索入力を `src/town/input.rs` へ移動。
   - `src/main.rs` をアプリのエントリポイントとスケジューリングのみに純化する。

## Decision

1. **ターン制戦闘システムの導入**:
   - 戦闘を `CommandInput` と `TurnResolving` のステートマシンで管理し、1ターンごとに「あなた」および仲間への指示を入力・実行する形式とする。
   - モンスター HP が 0 になった時点で直ちに勝利となり、街へ復帰する。
2. **主人公キャラクターの実体化**:
   - パーティ No.1 にプレイヤー自身（一般人）を配置し、戦闘・ステータス・宿屋回復の共通メンバーとして扱う。
   - 騎士アルヴィンは `ReserveRoster` に保持し、将来の王都アルカン酒場での編成入れ替えに備える。
3. **`src/main.rs` のモジュール再編**:
   - `src/ui/`（生成・表示・演出）、`src/battle/input.rs`（戦闘操作）、`src/town/input.rs`（探索操作）にファイルを分割し、`src/main.rs` をスリム化する。
