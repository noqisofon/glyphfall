# ADR-0012: メッセージ内下線語句選択方式による「おぼえる」UXの刷新

- Status: Accepted
- Date: 2026-09-15

## Background

ADR-0002で採用した手動キーワード記憶メカニクスは、現状「おぼえる」コマンドに★マークが付くことでNPCの発言に覚えられる話題があることを知らせるだけの実装になっている。
覚えられる単語そのものは`DialogueSession.learnable_topic: Option<String>`という1メッセージにつき1つだけの値として保持されており、発言文中では【封印の祭壇】のように全角括弧で囲んで手作業でマークしている。
この括弧書きの単語と`learnable_topic`に渡す文字列は、`dialogue.rs`の各`ask_topic`分岐で別々にタイプし直す必要があり、両者が食い違う（括弧内の単語と`learnable_topic`の文字列が一致しない）バグを作り込みやすい。
また衛兵の例（「この先は__マンティコア__がいるので閉鎖している」のように1文に複数の対象語がありうる）のような、1メッセージに複数の覚えられる単語が含まれるケースをそもそも表現できない。

## Circumstances

以下を満たす実装方法を検討した。

1. メッセージ本文中の対象語そのものに下線を引き、位置で覚えられる単語を示す。
2. 1メッセージに複数の対象語がある場合、「おぼえる」実行時にその複数候補から選べるようにする。
3. 既存の三分割対話UI（ADR-0002）・`TypewriterMessage`による1文字ずつの文字送り・罫線文字＋等幅フォントの見た目（`box_chars`モジュール、`CELL_PX`固定幅）を壊さない。
4. `Cargo.toml`でBevyは`0.15`に固定されている。この時点のBevy `Text`/`TextFont`にはtext-decoration相当（下線）を直接指定するAPIが無く、下線は何らかの形でグリフを並べて模す必要がある。
5. 話題の記憶順序が後続の文脈分岐（起点となる単語が文脈を決める、という既存メモ仕様）を左右するため、`PlayerInventory.topics: Vec<String>`への追加順は今のまま保たれなければならない。

## Rationale

下線描画の実現方式として3案を比較した。

- (a) メッセージ本文の描画自体を、罫線ボーダーと同じ「1マス1Textノードのグリッド」に作り直し、マス単位で色・装飾を制御する。最も柔軟だが、`TypewriterMessage`による1文字ずつの追記描画（`shown_chars`をインクリメントして`Text::new(shown)`を差し替えるだけの現行実装）を丸ごと書き直す必要があり、得られる価値に対して変更範囲が大きすぎる。
- (b) メッセージ本文は現行どおり単一の`Text`＋`TypewriterMessage`のまま維持し、その下（または重ねて）に、対象語の桁位置に合わせて半角アンダースコアなどのグリフを並べた別のオーバーレイTextノードを追加する。等幅フォント前提はすでに罫線ボーダー（`spawn_box_border`で1文字=1マスとして手動配置）で使われている手法であり、行ごとの文字数を数えて桁位置を算出するだけで済む。
- (c) 選択中の候補語をハイライトする手段として、Bevy 0.15の`TextSpan`によるリッチテキスト（1つの`Text`内で区間ごとに色を変える機能）や、(b)と同様のオーバーレイ重ね書きを使う。

(a)は変更範囲・リスクに見合わないため却下し、(b)＋(c)を採用する。既存の`TypewriterMessage`・罫線描画コードにほぼ手を加えず、オーバーレイノードを追加するだけで済み、ADR-0006が定めたグリフ・グリッド路線とも整合する。

下線を表示するタイミングは、要求どおり「表示完了後にのみ」とする。`shown_chars == full_text.chars().count()`になるまではオーバーレイを出さない。文字送り中の下線位置ズレや、まだ読めていない文字の下に下線が先回りして出てしまう違和感を避けられ、実装も単純になる。

データ構造は、括弧書きの単語と`learnable_topic`文字列を別々に手打ちする現行方式をやめ、`current_text`中の文字インデックス範囲（`LearnableSpan { start, end }`）だけを持たせ、実際に覚える文字列はその範囲を`current_text`からスライスして得る。これにより「本文中の下線位置」と「覚えられる単語」が構造的に一致し、表記ズレのバグが起きなくなる。括弧【】は下線と役割が重複する（どちらも「ここが対象語」を示す）ため、下線導入にあわせて本文中の括弧書きは廃止する。

複数候補がある場合の選択UIは、ADR-0011で導入した「コマンド→方向」の2段階選択（`CommandMenuStage::ChoosingCommand`→`ChoosingDirection`）と同じパターンを流用する。候補が0件なら現行どおり「見当たらない」、1件なら要求文書が明示的に許容する「自動選択」で即座に覚え、2件以上のときだけ候補選択の段階に入る。これにより単一候補の場合の操作感は変えず、複数候補のときだけ一手間増える。

記憶順序については、候補選択で確定できるのは1回の「おぼえる」実行につき1語のみとし、確定のたびに既存の`PlayerInventory::learn_topic`（`Vec<String>`の末尾に追加）をそのまま呼ぶ。複数の下線語を覚えたい場合はプレイヤーが「おぼえる」を複数回実行することになり、これは現行の1メッセージ1語の操作感と地続きであり、かつ「どちらを先に覚えたか」というプレイヤー操作起点の順序が今までどおり`topics`の並び順にそのまま反映される。`ask_topic`側の文脈分岐ロジックには一切手を入れる必要がない。

★マークは「このメッセージに覚えられる対象が存在するか」というメッセージ単位の通知として残し、判定条件を`learnable_topic.is_some()`から`!learnable_spans.is_empty()`に置き換えるだけとする。下線（個々の対象語の位置）と★（メッセージ単位の存在通知）の役割分担は、要求文書の意図どおりそのまま維持する。

## Decision

- `DialogueSession.learnable_topic: Option<String>` を `DialogueSession.learnable_spans: Vec<LearnableSpan>` に置き換える。`LearnableSpan`は`current_text`に対する文字インデックス範囲`{ start: usize, end: usize }`のみを持ち、覚える文字列はこの範囲を`current_text`からスライスして得る（文字列を別途保持・二重管理しない）。`ask_topic`の各分岐は、応答文の`current_text`をセットする際に対応する`learnable_spans`も併せて設定する。
- `dialogue.rs`内の会話文から【…】括弧によるマーキングを廃止し、下線がその役割を代替する。
- 描画側は`TypewriterMessage`の`shown_chars`が`full_text`の全文字数に達した時点でのみ、メッセージ本文Textノードと同じボックス内にオーバーレイTextノードを配置し、各行について対象語の桁位置に半角アンダースコア（`_`）を並べて下線を表現する。文字送り中は下線オーバーレイを出さない。
- `DialogueSession`に、ADR-0011の`CommandMenuStage`と同様のサブステージ`DialogueLearnStage`（`Talking` / `ChoosingLearnTarget { cursor: usize }`）を追加する。`[2]`（おぼえる）押下時の挙動を次のように変更する。
  - `learnable_spans`が空 → 現行どおり「新しく覚えられるキーワードは見当たらない。」を表示（変更なし）。
  - `learnable_spans`が1件 → 即座にその範囲をスライスして`inv.learn_topic()`を呼ぶ（現行の成功/既知メッセージはそのまま流用）。
  - `learnable_spans`が2件以上 → `ChoosingLearnTarget { cursor: 0 }`に遷移し、下線オーバーレイ中のカーソル位置の対象語だけ`palette::TEXT_HIGHLIGHT`（既存の黄色ハイライト色。新規パレット定義は追加しない）で色替えする。
- `ChoosingLearnTarget`中は`[W/S]`（または上下矢印、既存の話題選択操作に合わせる）で`cursor`を`learnable_spans`の配列順（本文中の出現順）で循環移動し、`[1]`/`Enter`でカーソル位置の対象語を確定して`Talking`に戻り、`[3]`/`Esc`で何も覚えずに`Talking`に戻る。
- 右ウィンドウの「おぼえる」ラベルの★表示条件を`learnable_topic.is_some()`から`!learnable_spans.is_empty()`に変更する。それ以外の★の役割（メッセージ単位の通知）は変えない。
- `PlayerInventory::learn_topic`と`ask_topic`の話題文字列ディスパッチ（起点となる単語が文脈を決めるルール）は変更しない。複数の下線語を覚える場合はプレイヤーが「おぼえる」を語の数だけ実行し、その実行順序がそのまま`topics: Vec<String>`の追加順になる。
