# ADR-0027: 世界設定パラメータをプリセット階層＋差分保存方式で管理する

- Status: Proposed
- Date: 2026-09-25

## Background

Daggerfall × DQ の世界作成時カスタム設定は、当初「識字率」「治安」等の個別項目（`settings` 内の
フラットなキー）として設計していた（ADR-0025：難易度＝世界の個性、という方針）。

しかしその後の議論で、以下のような独立した軸が次々と増えてきた。

- 時代（中世前期〜ルネッサンス期の史実準拠4段階）
- 様式（史実考証重視 or なろう系お約束）
- ギルド構成の地域差
- 隠しパラメータの可視化
- 亜人種族の有無

これらをフラットな `settings` に全部書き下ろす方式では破綻することが見えてきた。

## Circumstances

- 既存の前方互換性ルール（`formatVersion` 必須、知らないキーは無視してデフォルトにフォールバック）は
  維持する。
- 世界設定は「国 → 地域 → 町」の階層で継承・上書きされる構造を持つ。
- プレイヤーが世界設定を保存・共有する機能を前提とする（`daggerfall_dq_memo_addendum.docx`
  セクション5）。
- 設定項目は今後も増え続ける見込みで、ドキュメント・データ構造の両方が肥大化しやすい。

## Rationale

以下の3案を検討した。

### 案A：フラットな `settings` に全項目を直書き

シンプルだが、時代・様式ごとの既定値との関係が表現できず、項目が増えるたびにファイルサイズと重複が
増える。

### 案B：`eraPreset`／`stylePreset` の独立プリセット＋差分保存（採用）

`eraPreset`（時代）と `stylePreset`（様式）を独立したプリセットキーとして持ち、それぞれが既定値
テーブルを持つ。世界設定ファイルには既定値からの上書き分のみを差分として保存する。

- **時代4段階**（`early_medieval` / `high_medieval` / `late_medieval` / `renaissance`）は史実の
  ヨーロッパ史に準拠し、時代が進むほど制度・インフラが整う設計とする。全時代でモンスターの存在を
  前提とし、「移動宮廷＝巡回討伐を兼ねた武装集団」「街道の安全＝王権の正統性の指標」という読み替えで
  史実とファンタジー要素を両立させる。
- **様式**は時代を選ばない軸として独立させ、`narrowpa`（なろう系お約束、ゲーム的利便性が常識）と
  `historical_fantasy`（史実の重みを残した折衷様式、仮称イバラギーッパ）を公式プリセットとする。
  ユーザー定義の様式も同じ構造で保存・共有可能にする。
- **ギルド構成**（宿屋・酒場・冒険者/協会の統合パターン）、**隠しパラメータの可視化**
  （`hiddenParameters`：`hidden` / `appraisable` / `visible`）、**亜人種族の有無**（`demihumans`）も
  同じプリセット階層に乗せる。
- **差分保存**により、世界設定ファイルは「その世界の個性＝プリセットからの差分」だけを表現でき、
  ファイルサイズも抑えられる。

### 案C：世界生成をルールエンジン化し、全パラメータを動的計算する

将来的に検討の余地はあるが、現時点では過剰設計と判断し見送る。

## Decision

- 世界設定JSONのトップレベルに `eraPreset` と `stylePreset` を独立したキーとして持つ。
- 各プリセットはゲーム側が既定値テーブルを保持し、世界設定ファイルには既定値からの上書き分のみを
  保存する（差分保存方式）。
- ギルド構成・`hiddenParameters`・`demihumans` も同じ階層構造（国→地域→町の継承・上書き、
  プリセット既定値＋個別上書き）に統一する。
- `demihumans.races` は将来の特性拡張（`traits`：寿命・得意分野・種族間関係等）に備え、当初から
  文字列配列ではなくオブジェクト配列（`{ "id": "elf" }`）として持つ。
- `damselEventFrequency` 等、時代・様式に連動しない「世界の味付け」項目は、プリセットとは独立した
  項目として `settings` 内に残す。
- 既定値テーブル自体のバージョニング方法は未決事項として残す（既定値を後から調整した場合の既存
  世界設定への影響が未整理）。
