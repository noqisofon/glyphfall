# ADR-0002: 三分割会話UIと手動キーワード記憶（「覚える」メカニクス）

- Status: Accepted
- Date: 2026-09-13

## Background

現代のRPGでは、NPCの発言やクエスト関連のキーワードは自動的に「クエストログ」や「会話ログ」に蓄積され、目的地にはマップマーカーが付くのが標準となっている。
この利便性はプレイヤーの負担を減らす一方で、「NPCの話を真剣に聞く必要性」や「会話の中から重要そうな単語を手帳にメモする」という冒険者としての主体的な情報収集の緊張感を奪っている。

## Circumstances

NPCとの「はなす」コマンドにおける画面構成と、情報獲得のUXを検討した。
以下の3つのアプローチが考えられた：

1. **自動ジャーナル方式（現代RPG標準）**: 会話したキーワードやクエストが自動的に整理・記録される。
2. **フリーテキスト入力方式（Ultima / Wizardry IV 的アプローチ）**: 会話中にキーボードで単語を入力して尋ねる。
3. **コマンド選択＋手動ストック方式（本作案）**: ドラクエ的な選択式UIを保ちつつ、NPCの発話からプレイヤーが自ら単語を選んで「覚える」を実行する。

## Rationale

自動ジャーナル方式（1）は快適だが、「聞き逃したら詰む緊張感」が完全に失われてしまう。
フリーテキスト入力方式（2）はクラシックPCゲームの渋さがあるものの、入力の手間が大きすぎ、コントローラ対応や表記揺れの吸収といった実装コストも高い。

そこで、DQのコマンド選択の簡便さを維持しながら「能動的にメモを取る感覚」を再現できる（3）を採用した。
画面を三分割（左：話題、中央：メッセージ、右：行動）し、NPCの発話に含まれる単語をプレイヤーが明示的に「覚える」コマンドで話題ウィンドウにストックしなければ、二度とその話題を他人に振ることができない仕様とする。

さらに、誰が何を言っていたかの一覧化・整理はシステム側で一切行わず、プレイヤー自身の記憶や現実のメモ頼みにする。これにより、「聞き逃した」「あのNPCが言っていたのはこれか！」という当事者意識が保たれる。

## Decision

「はなす」コマンドの画面レイアウトを三分割（左：話題、中央：メッセージ、右：行動）とする。
NPCの発言に出てきた単語は、プレイヤーが自ら「覚える」コマンドを実行して話題ウィンドウに追加する手動記憶メカニクスを採用する。システムによる自動一覧化は行わない。
