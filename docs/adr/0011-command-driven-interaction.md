# ADR-0011: コマンド駆動インタラクト（Zキー→コマンド選択→方向選択）の採用

- Status: Accepted
- Date: 2026-09-15

## Background

これまでの実装では、プレイヤーが宝箱・案内看板・NPC・お店のタイルに向かって移動入力（ぶつかり）を行うと、
自動的に会話（`StartDialogue`）や宝箱開封（`ChestOpened`）が発生していた。
これは現代のRPGに広く見られる「隣接・接触しただけで自動的に調べる/話しかける」利便性重視の設計である。

## Circumstances

昔のドラクエ（I〜IV系）が持っていた、Zキー（旧作ではAボタン等）でコマンドウィンドウを開き、
「しらべる」「はなす」等のコマンドを選び、さらに方向を選んでようやく判定が行われるという、
あえて手間のかかる操作系をどう再現するかを検討した。

1. **接触自動判定方式（現行実装）**: タイルに重なる/ぶつかるだけで会話や宝箱開封が自動発生する。
2. **コマンド駆動方式（本ADR案）**: Zキーでコマンドウィンドウを開き、コマンドと方向を明示的に選択しないと何も起こらない。

## Rationale

接触自動判定方式は快適だが、「何にでも触れれば勝手に反応してくれる」という受動的なプレイ感覚しか生まない。
本作はADR-0002の手動キーワード記憶に代表されるように、プレイヤーの能動的な行動を要求する渋い操作系を志向しており、
インタラクトの起点をコマンド選択に一本化することでその一貫性を保てる。

また、「しらべる」コマンドは対象がモノ・地形であることを前提にしたラベルだが、方向の先が人物だった場合には
「みる」という軽い一発判定（外見・様子の一言確認）に呼称ごと切り替わる方が直感的である。
「はなす」はより踏み込んだ本格対話（三分割UI、ADR-0002）に遷移するコマンドとして明確に区別する。

「ぬすむ」など将来追加されるコマンドも見据え、コマンドと対象可能な型の対応（しらべる→地形/NPC/宝箱、
はなす→NPCのみ、ぬすむ→盗める属性を持つNPC/モンスターのみ）を素直に拡張できるテーブル的な構造
（`CommandKind` と対象種別 `TargetKind` の組み合わせ）を採用する。

## Decision

- 隣接・接触しただけでは何も起きない。移動でNPC・お店・案内看板・宝箱のタイルにぶつかった場合は、
  単に移動がブロックされるだけで、会話や宝箱開封は発生しない。
- プレイヤーは以下の手順を踏んでインタラクトする。
  1. `Z` キーでコマンドウィンドウを開く（`しらべる`／`はなす`／`どうぐ`／`ぬすむ`）。
  2. `W/S` でコマンドを選択し、`1/Enter` で決定する。
  3. （`どうぐ` 以外は）方向キーでインタラクト対象の方向を選択する。
  4. その方向のマスに対応する対象があれば判定・結果を表示し、なければ「なにもない」等の空振りを表示する。
- `しらべる` は対象が人物系タイル（NPC・宿屋・酒場・道具屋の店主）の場合、メニュー上のラベル自体が動的に
  `みる` に変わる。`みる` は外見・様子を確認する程度の軽い一発判定テキストのみを返し、ADR-0002の三分割UIには
  遷移しない。
- `はなす` はNPC系タイルのみを対象とし、ADR-0002の三分割UI（メッセージ／話題／行動）による本格対話に遷移する。
  対象がいない方向を選んだ場合は「そこには話せる相手がいない。」と空振りする。
- `どうぐ` は方向選択を経由せず、コマンド決定と同時に所持品一覧を表示する（今後のフィールドでのアイテム使用の
  入口として拡張予定）。
- `ぬすむ` は本ADRの時点では対象種別の判定のみ実装し、成功率や盗まれた側の反応（影響度システムとの接続）は
  未検討・今後の課題として、暫定の「まだ準備中」メッセージを返す。
