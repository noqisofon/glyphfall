# ADR-0028: 名詞先行型「たずねる」対話システムと知識ポインタ・社会的障壁

- Status: Proposed
- Date: 2026-09-28

## Background

従来のGlyphfallの会話システム（ADR-0002 / ADR-0012）は、下部三分割UI上で相手に話題を「振る」
単一アクションと、本文中の下線語句を「おぼえる」機能で構成されていた。
しかし、情報収集そのものが探索・クエスト誘導の主軸となる「Daggerfall × DQ」の世界において、
「ここ・トリポリはどこ？」「マンティコアの弱点は何？」といった具体的な問いかけや、
語順（起点となる単語が文脈を決める）、相手の知識量・警戒度に応じた返答の機微を表現するには、
単一キーワードの投げかけでは表現力が不足していた。

## Circumstances

- ADR-0002（三分割会話UI）の枠組みを維持しつつ、「たずねる」アクションを多段階の文脈構成へと
  機能拡張する必要がある。
- 「たずねる」の操作において、語順は「起点となる単語が文脈を決める」ルールに従い、
  名詞先行（対象 → [属性] → 疑問詞）で統一する。
- 属性（「弱点」「生態」等）は聞き方（動詞側）ではなく、話題ウィンドウ（名詞側）の語彙として扱う。
- 「ここ」「私」「あなた」は固定知識ノードではなく、動的に解決される文脈代名詞（トークン）として
  扱う必要がある（「誰？→私」による評判照会や記憶喪失ジョークの成立を含む）。
- NPCが「知らない」場合、詳しい人物への参照（ポインタ）を返すことがあるが、ポインタ先の固有名詞は
  自動開示せず、本文中で下線表示しプレイヤーが手動で「おぼえる」設計を崩さない。
- ポインタで所在が判明しても、面会・謁見には社会的障壁（第三者が発行した紹介状、評判など）が挟まる。
- UI表現として、階層メニュー方式とカードUIメタファー（手札を並べる感覚）の双方が検討されているが、
  どちらを主軸とするかは未決である。

## Rationale

1. **手動記憶ルールの徹底**:
   ポインタによる情報開示であっても自動登録は行わず、ADR-0002 / ADR-0012 の「台詞から手動でおぼえる」
   サイクルを一貫させることで、聞き逃すと辿れない緊張感とメモを取る手触りを担保する。
2. **第三者評価による社会的障壁の分離**:
   謁見条件は静的な条件（`RequiresItem` 等）として定義し、紹介状の発行等は依頼発注側のNPCが
   担う構成とすることで、プロ値契約書や公認資格と同様の「実績を第三者が評価・保証する」構造を保つ。
3. **段階的MVP開発**:
   まずは `Answer`、`Pointer`（社会的障壁付き）、文脈トークン、新人判定（`NewbieJudgment`）で
   基本ループのテストチェーンを成立させ、言い淀み（食い下がり）や秘匿（目星判定）は次段階とする。

## Decision

- 本決定は ADR-0002（三分割会話UI）を置き換えるものではなく、「たずねる」コマンドの多段化として拡張する。
- 行動枠で「たずねる」起動後、話題枠の「対象名詞」→「（任意）属性名詞」→聞き方枠の「疑問詞」を選択する
  名詞先行フローを採用する。
- 「ここ」「私」「あなた」は動的解決される文脈トークン（`QuerySubject::Here / Me / You`）として扱う。
- ポインタ先の人物・地名は自動追加せず、本文中の下線語句として提示し手動「おぼえる」を必須とする。
- 謁見・面会障壁は `AccessBarrier` として静的に定義し、紹介状等のアイテム提示や評判を要求する。
- UIの具現化（階層メニューとカードUIの統合形態）はMVP検証用として暫定的に階層＋スロット表示を採用し、
  本決定のステータスは Proposed のまま触り心地を検証する。
