# ADR-0009: レトロ2Dドット絵／スプライト・ハイブリッドの採用

- Status: Accepted
- Date: 2026-09-14
- Supersedes: [ADR-0007](0007-pure-glyph-ascii-graphics.md)

## Background

ADR-0007 では、アセット調達コスト最小化と「Glyphfall」のコードネームに基づき、文字・罫線記号のみで描画する「ピュア・グリフ／ASCIIアート路線」を採用していた。
しかし、実際に等幅文字グリッドによる街移動（ADR-0008）を実装・プロトタイプ検証した結果、以下の重大な問題が判明した：

1. **フォント環境による文字幅の不一致（East Asian Width問題）**:
   - 記号（`♠`, `§`, `░` 等）がフォントやOS環境によって半角（幅1）または全角（幅2）として解釈され、行ごとに文字幅が狂って矩形グリッドが激しく崩壊する。
   - プロポーショナルフォント環境では文字ごとの幅差により格子状の配置が成立しない。
2. **プレイ視覚負荷と参入障壁**:
   - テキスト文字のみで構成されたマップは、プレイヤーにとって直感的な地形把握が難しく、認知負荷が過大となる。

## Circumstances

グラフィック方針の再検討にあたり、以下の選択肢を比較した：

1. **厳密な文字セル個別ノード化（ASCIIグリッドの維持）**:
   - 1文字ごとにUIノードを生成して文字を中央配置し、完全な半角ASCII文字に限定する。
   - レイアウト崩れは防げるが、依然として文字記号特有の記号性・抽象度の高さ（視覚的わかりにくさ）が残る。
2. **レトロ2Dドット絵／スプライトへの切り替え（本案）**:
   - 枠線やメッセージ・ステータスUIにはDQ的な親しみやすい罫線テキストUIを維持しつつ、中央のゲーム画面（街マップ・ダンジョン・モンスター）を16×16ピクセルのクラシックな2Dドット絵（ピクセルアート）で描画する。
   - 当初懸念されたアセットコストは、コード内で直接16×16のレトロドット絵テクスチャ（PC-98 / SFC風カラー）をプロシージャル生成することで解決する。

## Rationale

選択肢2（レトロ2Dドット絵への切り替え）を採用する理由は以下の通り：

1. **フォント問題の完全な根絶**:
   - ピクセル単位のビットマップ（テクスチャ）として描画するため、どのようなOS・フォント環境であっても1ピクセルのズレもなく完璧に美しい格子画面が表示される。
2. **ドラクエ的親しみやすさの真の実現**:
   - 主人公、仲間たち（赤兜の戦士、道化帽の遊び人、とんがり帽の魔法使い、白銀の騎士）、街並み（石畳、水路、木々、扉）が視覚的に生き生きと表現され、ADR-0001で掲げた「ドラクエの親しみやすさ」が最大限に発揮される。
3. **自律完結型ドット絵エンジン**:
   - コード内でピクセルデータを直接定義・生成するため、外部画像ファイルへの依存がなく、即座に安定動作する。将来的にユーザーが外部PNG素材へ差し替えることも容易。
4. **視界制限（FOV）の表現力**:
   - 松明の光による明暗差や影を、文字ではなくピクセルのカラーブレンド（シャドウマスク）として滑らかに表現できる。

## Decision

ADR-0007（ピュア・グリフ表現）を改訂し、本作のグラフィック方針として**「レトロ2Dドット絵／スプライト・ハイブリッド」**を採用する。
中央画面は16×16ピクセルのドット絵テクスチャとして描画し、外枠および会話・ステータスUIはドラクエ風テキストウィンドウを維持する。
