# ADR-0018: 確率的な物語テンプレート部屋によるCave生成のハイブリッド化

- Status: Accepted
- Date: 2026-09-16

## Background

ADR-0017で、B1Fの固定マップをセルオートマトン法による完全ランダムな洞窟生成
（`DungeonGenKind::Cave`）に置き換えた。この際、旧固定マップが持っていた
「宝物庫」「水没した礼拝堂」「牢獄区画」という手作りの物語的ゾーニングは、
「B1Fそのものを置き換える」という判断（ユーザー判断）の帰結として失われた
（ADR-0017 Background）。

しかし「潜るたびに姿を変える」という完全ランダム性の価値と、「宝物庫に踏み込んだ
ときの高揚感」「静かな礼拝堂の不気味さ」「牢獄区画の緊張感」といった物語的な
記名性は、本質的にトレードオフの関係にはない。両方を得る方法として、
「完全ランダムな洞窟の中に、確率的に少数の手作りテンプレート部屋を上書きで
挿入する」というハイブリッド案が持ち上がった。これがADR-0018のスコープである。

## Circumstances

実装にあたり、以下の制約・論点があった。

1. **ADR-0017の到達可能性保証を壊してはならない**: ADR-0017 Rationale 3.で
   確立した「宝箱・魔物シンボルは、他のマスを巻き添えで塞ぐ配置になっていれば
   取り消す」というガード（`try_place_tile`、旧`build_map`内の無名ループ）は、
   このADRで導入するテンプレート部屋にも同様に適用する必要がある。テンプレート
   部屋は宝箱・魔物シンボルを複数マスまとめて配置するため、1マスずつの
   ランダム配置よりも到達不能化のリスクが高い。
2. **既存のタイル語彙で表現する**: ADR-0017 Rationale 4.で、`IronGateClosed`
   （鉄格子扉）・`Water`（水没床）は物語的ゾーンに紐づく装飾として意図的に
   除外されていた。今回もこの方針を維持し、`IronGateClosed`・`Water`は
   使わない。`DungeonFloor` / `ChestClosed` / `MonsterSymbol`という、
   Cave生成が既に使っている語彙の範囲内で3種類を作り分けることにした
   （宝物庫＝宝箱の密集、牢獄区画＝魔物シンボルの密集、礼拝堂＝装飾なしの
   空き部屋）。
3. **配置座標の決定性**: ADR-0017 Rationale 6.で、下り階段の位置選びに使う
   `bfs_distances`の返り値を`HashMap`から行優先の`Vec`に変更し、同じシードから
   常に同じ結果になるようにした経緯がある。テンプレート部屋の候補地選定も
   この`bfs_distances`の結果（降順ソート）を再利用するため、ソートに
   `sort_by`（安定ソート）を使い、同着だった場合のタイブレークも決定的になる
   よう配慮した。
4. **下り階段・上り階段・入口との衝突**: テンプレート部屋の候補地は「入口から
   最も遠い側」から探すため、既存ロジックが下り階段を置く場所（同じく
   「最も遠いマス」）と競合しやすい。両方が同じマスを取り合うと、テンプレート
   矩形の中に階段が埋もれてしまう。

## Rationale

1. **個数抽選は0/1/2個の重み付き乱数**: 「潜るたびに毎回同じ物語部屋が出る」の
   も「毎回2個フル装備で出る」のもランダム性を損なうため、0個(25%)を最多とし、
   1個(60%)を基本、2個(15%)を稀なボーナスとする配分にした。
   （`choose_template_room_count`）
2. **候補地は下り階段・上り階段・入口を除いた「入口から遠い側」から探す**:
   `bfs_distances`の結果を距離降順にソートし、遠い側から順に「5×5の矩形が
   全部region内に収まり、かつ入口・上り階段・下り階段のいずれとも重ならない
   か」を判定する。最初に見つかった座標を採用する。これにより、Circumstances
   4.の階段との座標衝突を避けつつ、「テンプレート部屋は洞窟の奥まった場所に
   ある」という手触りも自然に得られる。矩形が見つからなければ無理に置かず、
   その分は通常のランダム配置に回す（`find_template_slots`）。
3. **2個目はBFS距離差が一定以上離れた場所から探す**: 2個目を探す際は、1個目の
   矩形と重ならないことに加え、入口からのBFS距離が1個目と
   `TEMPLATE_MIN_DISTANCE_GAP`（5マス）以上離れていることを要求する。これは
   「2個出た場合に隣り合った場所に固まって出る」ことを避け、洞窟の別々の
   奥まった場所にそれぞれ配置されるようにするための最低限のヒューリスティック
   である。
4. **テンプレートの中身はラフな差別化で十分**: 「潰し合わない程度の作家性」を
   狙い、以下の3種類とした。
   - **宝物庫（Treasury）**: 5×5の中央3×3を`ChestClosed`で埋める。周囲1マス
     の床は残し、部屋の外周は通路として機能させる。
   - **礼拝堂（Chapel）**: 何も上書きしない（既存の`DungeonFloor`のまま）。
     「洞窟の中にぽっかり空いた、何もない静かな小部屋」という体験は、タイルを
     置かないことそのもので表現できる。
   - **牢獄区画（Prison）**: 5×5の四隅寄り4マスに`MonsterSymbol`を配置し、
     見張りが四方に立っているような密集感を出す。
   種類は3つからランダムに1つ選ぶ（`random_template_kind`）。
5. **配置は既存の到達可能性ガードを1タイル単位で再利用する**: ADR-0017の
   宝箱・魔物配置ループから、1タイル配置＋到達可能性チェック＋ロールバックの
   部分を`try_place_tile`として切り出し、通常のランダム配置とテンプレート部屋
   の両方から呼び出す形にした。これにより、テンプレート部屋が仮に隘路に
   かかってしまっても、個々のタイル単位で「他のマスを巻き添えにする配置は
   取り消す」というADR-0017の保証がそのまま効く。テンプレート部屋全体を
   丸ごと配置するか諦めるかの二択にはしていない（一部のタイルだけ床に
   戻って部屋が欠けた形になることを許容する）。
6. **テンプレートが使った矩形は丸ごと以後の配置対象から除外する**: 個々の
   タイルが実際に宝箱・魔物になったかどうかに関わらず、テンプレート矩形の
   25マス全部を「使用済み」として、後段の宝箱2個・魔物1個のランダム配置候補
   から除外する。これにより、テンプレート部屋の床（礼拝堂の空きマスなど）に
   ランダム配置の宝箱が紛れ込んで座標が重複する事故を防ぐ。

## Decision

`core::town::dungeon_gen`の`build_map`内、宝箱・魔物のランダム配置より前に、
以下の処理を追加する。

1. `choose_template_room_count`で0個(25%)/1個(60%)/2個(15%)の重み付き乱数を
   引き、今回のB1Fに出すテンプレート部屋の個数を決める。
2. 下り階段の配置に使う`bfs_distances`の結果を入口からの距離で降順ソートし
   （`sort_by`による安定ソートで決定性を維持）、`find_template_slots`が
   遠い側から順に「5×5の矩形（`TEMPLATE_ROOM_SIZE`）がregion内に収まり、かつ
   入口・上り階段・下り階段と重ならないか」を判定して座標を選ぶ。2個目は
   1個目と矩形が重ならず、かつBFS距離差が`TEMPLATE_MIN_DISTANCE_GAP`
   （5マス）以上離れていることを追加で要求する。条件を満たす座標が
   見つからなければ、その分は通常のランダム配置に回す。
3. 選ばれた矩形ごとに、`TemplateRoomKind`（`Treasury` / `Chapel` / `Prison`）
   からランダムに1つを選び、`template_layout`が定義する局所タイル配置
   （宝物庫＝中央3×3を`ChestClosed`、礼拝堂＝上書きなし、牢獄区画＝四隅寄り
   4マスに`MonsterSymbol`）で上書きする。個々のタイル配置は
   `try_place_tile`（ADR-0017の到達可能性ガードを1タイル単位に切り出した
   共通関数）を通し、他のマスを巻き添えで塞ぐ配置は床に戻す。
4. テンプレート矩形が使った25マスは、後段の「残りの床マスへ宝箱2個・魔物
   シンボル1個をランダム配置する」処理の候補から除外し、座標の重複を防ぐ。

`IronGateClosed`・`Water`は引き続き使わず（ADR-0017の方針を維持）、新しい
`TileType`も追加しない。テストは以下の3点を追加・拡充する。

- `test_template_room_count_matches_expected_distribution`:
  `choose_template_room_count`を20万シード分呼び、0/1/2個の出現比率が
  25%/60%/15%に対して誤差2ポイント以内であることを検証する。
- `test_template_slots_never_overlap_across_many_cave_shapes`: 実際の洞窟
  生成パイプライン（`random_fill`→`smooth_step`→`flood_fill`→
  `bfs_distances`）を500シード分再現し、`find_template_slots`が2個の矩形を
  返した場合にそれらが座標的に重ならないこと、かつ両方ともregion内に
  完全に収まっていることを検証する。
- `test_cave_generation_is_connected_across_many_seeds`（既存、ADR-0017）:
  検証対象のシード数を30から200に拡大した上で、許容する非歩行タイル数を
  固定値（宝箱2個・魔物1個分の"3"）ではなく、実際にマップ上へ置かれた
  `ChestClosed` / `MonsterSymbol`の枚数を数えた動的な値に変更した。これにより
  テンプレート部屋が0個・1個・2個のどのケースでも、「入口から歩いて到達
  できるマス数＋非歩行の装飾タイル数」が生成時の連結領域の下限
  （`CAVE_MIN_FLOOR_TILES`）を下回らないことを検証でき、テンプレート部屋の
  有無によらず「入口から連結している」という保証を確認できる。
