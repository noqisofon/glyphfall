**MVP具体化：漂着＋冒険者ギルド免許のシナリオ**

これまでの `Pointer` / `AccessBarrier` の抽象的なテストチェーン（マンティコア／団長）とは別に、実際に検証したい具体的な導入シナリオが固まりました。既存の実装がそのまま使える形なので、共有します。

**導入**
船に乗っていたら、◯◯大陸の海岸に流れ着く。所持品も身元を示すものもない状態でスタートする。

**身元不明の状態**
- 評判（`Reputation`）はゼロ、顔見知りもゼロ。「お前のようなやつには」という門前払いが最初から効く状態
- 身元不明の間は宿に泊まれない。これが、近くの洞穴で野宿する動機になる
- 誰？→私、とたずねると「記憶喪失なのですか？」と返るようなジョークもこの設定に自然に乗る

**洞穴の位置づけ**
- 拠点機能（保管庫や馬車置き場など）は持たせない、ただの野宿スポットの一つ
- 免許取得後も戻ってこられるが、特に意味はない（住所登録は別の場所になるため）

**免許取得の流れ**
- 近くの町の冒険者ギルドで免許を取得すると、身元が立つ
- 免許の取得条件は「衛兵の依頼を数件こなす」こと（実績の積み上げ）
- 免許取得時に、宿屋兼酒場が正式な住所として登録される（多くの町では、宿屋・酒場・依頼所が一つの看板を兼ねる三者統合型のギルド構成になっているため）
- 免許取得後は宿に泊まれるようになり、洞穴を使う理由は自然になくなる

**既存実装との対応**
このシナリオは、直前に実装した「衛兵の依頼をこなす→紹介状→団長への謁見」の連鎖と構造的に同一です。

- 衛兵の依頼NPC：達成時に `AccessBarrier::RequiresItem("冒険者ギルド免許")` に相当するアイテム（免許）を発行する側
- 宿屋（宿泊アクション）：この免許を持っていない間は宿泊を拒否する側の障壁
- 今回追加された `RequiresReputation` も、この文脈で活きるはずです。「素性の知れない者には貸さない」を評判軸の障壁として検証してほしいところです（前回の報告ではこの型がテストされていませんでした）

**検証したい対話チェーン（MVP一周）**
1. 洞穴で目覚める（所持品なし、評判ゼロ）
2. 町の住人に「ここ→どこ？」「ギルド→どこ？」とたずね、ギルドの場所を知る
3. ギルドで「免許→知っている？」等をたずね、取得条件（衛兵の依頼を数件）を知る
4. 条件を満たして免許を取得
5. 免許を提示して宿に宿泊できるようになる（住所登録）

**スコープ外にしたいこと**
- 洞穴に拠点機能を持たせること
- 書類読解スキルなど、免許以外の身分証明の仕組み
- 免許取得後に洞穴へ戻る動線の作り込み

この一周が通れば、既存の `Pointer` / `AccessBarrier` の型がそのまま実データで機能することの確認になります。UIの実装や `TrailingOff` / `Concealed`（ステージ2）は、このシナリオが通ってからで問題ないはずです。
